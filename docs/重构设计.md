# 项目分包重构设计

> 状态：已按确认方案落地（**不再支持 Firefox**）。公共逻辑在 `shared/copy-runtime`，产物出口为仓库根 `dist/`。

## 1. 需求概述

把仓库按运行时拆成两类独立产品线：

1. **油猴 / 篡改猴脚本（Userscript）**
2. **Chrome / Chromium 浏览器扩展（Extension，含 Firefox Gecko）**

两类产品使用 **不同的源码目录** 和 **不同的打包出口**，根脚本、workspace、CI 都按这个边界组织。

## 2. 现状诊断

### 2.1 当前结构

```text
packages/                    # 油猴脚本与扩展混放
  copy/                      # 油猴：文本选中复制
  copy-currency/             # 油猴：通用解除限制
  site-modify/               # 油猴：站点魔改
  force-copy/                # 扩展：Force Copy（rspack，Chrome/Firefox）
  clipboard2markdown/        # 扩展：静态 MV3，无构建
rollup.config.js             # 根级统一打三个油猴脚本
publish-scripts.sh           # 油猴生产构建
.output/                     # 油猴产物（已入库）
```

### 2.2 主要问题

| 问题             | 说明                                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 产品边界不清     | `packages/*` 同时装油猴和应用扩展，新人无法从目录判断产物形态                                                                 |
| 构建所有权混乱   | 油猴构建挂在仓库根（`rollup.config.js`），包内几乎没有 `dev/build`；扩展构建挂在 `force-copy`                                 |
| 出口不统一       | 油猴 → `.output/`；Force Copy → `packages/force-copy/build`、`build-gecko`；clipboard2markdown 没有独立出口，只能加载源码目录 |
| CI 出口对不上    | `.github/workflows/deploy-scripts.yml` 部署 `FOLDER: dist`，实际油猴产物在 `.output/`                                         |
| 跨产品深路径耦合 | `force-copy` 通过 workspace 依赖 `copy` / `copy-currency`，并直接 `import "copy/src/..."`                                     |
| 脚本不可移植     | `publish-scripts.sh`、`rm -rf build` 依赖 bash/Unix，Windows 本地构建不友好                                                   |
| 文档路径过期     | `packages/copy/README.md` 仍指向旧路径 `src/copy`                                                                             |

### 2.3 当前依赖关系（必须保留行为）

```text
force-copy
  ├── copy/src/constant/event
  ├── copy/src/utils/instance
  ├── copy/src/utils/copy
  └── copy-currency/src/utils   (styles.insertCSS / removeCSS)

油猴脚本彼此独立，无互相依赖
clipboard2markdown 完全独立
```

`copy` 与 `copy-currency` 既是油猴入口，又被扩展当运行时库用。重构时 **不能切断这条复用**，只能换一种更干净的引用方式。

## 3. 目标结构

```text
.
├── scripts/                         # 油猴 / 篡改猴
│   ├── copy/
│   ├── copy-currency/
│   └── site-modify/
├── extensions/                      # 浏览器扩展
│   ├── force-copy/
│   └── clipboard2markdown/
├── shared/                          # 跨产品可复用运行时（第二阶段抽出）
│   └── copy-runtime/
├── dist/
│   ├── userscripts/                 # 油猴唯一出口
│   │   ├── copy.user.js
│   │   ├── copy-currency.user.js
│   │   └── site-modify.user.js
│   └── extensions/                  # 扩展唯一出口
│       ├── force-copy/
│       │   ├── chromium/
│       │   └── gecko/
│       └── clipboard2markdown/
├── tooling/                         # 共享构建配置（rollup 油猴基座等）
├── package.json                     # 仓库级编排脚本
├── pnpm-workspace.yaml
└── README.md
```

### 3.1 workspace

```yaml
packages:
  - "scripts/*"
  - "extensions/*"
  - "shared/*"
```

根目录不再把业务包平铺在 `packages/`。

### 3.2 打包出口约定（硬约束）

| 产品                       | 开发加载位置                             | 生产出口                                                              |
| -------------------------- | ---------------------------------------- | --------------------------------------------------------------------- |
| 油猴 `copy`                | `dist/userscripts/copy.user.js`          | 同左；UserScript 头写在 `.user.js` 内 |
| 油猴 `copy-currency`       | `dist/userscripts/copy-currency.user.js` | 同上                                                                  |
| 油猴 `site-modify`         | `dist/userscripts/site-modify.user.js`   | 同上                                                                  |
| 扩展 `force-copy` Chromium | `dist/extensions/force-copy/chromium`    | 同左；zip 另出到 `dist/extensions/force-copy/force-copy-chromium.zip` |
| 扩展 `force-copy` Gecko    | `dist/extensions/force-copy/gecko`       | 同左；zip 另出                                                        |
| 扩展 `clipboard2markdown`  | `dist/extensions/clipboard2markdown`     | 构建时把静态资源复制到该目录                                          |

`dist/` 作为生成物，加入 `.gitignore`。油猴若仍需 gh-pages 发布，由 CI 把 `dist/userscripts` 同步到发布分支，不再把产物提交进 `master`。

旧目录 `.output/`、`packages/force-copy/build`、`build-gecko` 在迁移完成后删除。

## 4. 构建与脚本约定

根 `package.json` 只做编排，不做业务实现：

```json
{
  "scripts": {
    "dev": "pnpm run dev:scripts",
    "build": "pnpm run build:all",

    "dev:scripts": "pnpm --filter \"./scripts/**\" run dev",
    "build:scripts": "pnpm --filter \"./scripts/**\" run build",

    "dev:extensions": "pnpm --filter \"./extensions/**\" run dev",
    "build:extensions": "pnpm --filter \"./extensions/**\" run build",

    "dev:force-copy": "pnpm --filter force-copy run dev",
    "build:force-copy": "pnpm --filter force-copy run build",
    "dev:force-copy:gecko": "pnpm --filter force-copy run dev:gecko",
    "build:force-copy:gecko": "pnpm --filter force-copy run build:gecko",

    "build:all": "pnpm run build:scripts && pnpm run build:extensions"
  }
}
```

各包自己声明 `dev` / `build`：

- `scripts/*`：Rollup + `rollup-plugin-userscript-metablock`，入口、`meta.json` 留在包内
- `extensions/force-copy`：继续 rspack，只改 `output.path`
- `extensions/clipboard2markdown`：增加最小 `build` 脚本，把 `manifest.json`、html、js、css、svg 复制到 `dist/extensions/clipboard2markdown`

油猴 Rollup 配置从根 `rollup.config.js` 下沉到 `tooling/rollup.userscript.js`，由各脚本包引用，避免三个包复制一份插件列表。

Windows 兼容：生产构建不再依赖 `bash publish-scripts.sh` / `rm -rf`，改为 Node 脚本或 `rimraf` + cross-env（仅在确实需要时加依赖）。

## 5. 共享代码策略

### 5.1 原则

第一阶段 **先搬家、后抽核**：目录和出口先落地，业务文件内容尽量原样移动，保证油猴和扩展行为不变。

第二阶段再抽 `shared/copy-runtime`，专门承接现在被扩展深引用的部分：

- `copy/src/constant/event.ts`
- `copy/src/utils/instance.ts`
- `copy/src/utils/copy.ts` 中被扩展用到的常量
- `copy-currency/src/utils.ts` 的 `styles`

油猴入口（`index.ts`、站点 modules、meta）留在 `scripts/copy`、`scripts/copy-currency`。扩展不再 `import "copy/src/..."`，改为 `import "copy-runtime/..."`。

### 5.2 为什么不第一阶段就抽核

- 深路径引用面不大（约 10 个文件），搬家后 workspace 别名仍能工作
- 抽核会碰到导出边界、类型、打包 tree-shaking，容易和「先分目录」缠在一起，回归面变大

### 5.3 明确不抽的内容

- `copy/src/modules/*` 各站点适配：油猴专用，扩展有自己的 `inject/modules`
- `site-modify` 全部：与扩展无关
- `force-copy` 的 popup / worker / bridge：扩展专用
- Vue 2（仅 `site-modify`）和 React 17（仅 `force-copy`）继续隔离，不统一框架

## 6. 优化项（在分包落地后做，不阻塞主重构）

1. **CI 与出口对齐**：gh-pages 部署 `dist/userscripts`，不再写死不存在的 `dist`
2. **产物不进 git**：`.output` 停止提交；发布走 CI
3. **各包 scripts 补齐**：`lint:ts`、`dev`、`build` 每个业务包都能独立跑
4. **tsconfig 按产品拆 references**：根 `include: packages/*/src` 改为 scripts / extensions / shared 三份
5. **clipboard2markdown 正规化**：有 `build`、有出口目录，加载扩展时不再指向源码树
6. **README 分层**：根 README 只讲产品线和命令；各包 README 讲安装与 Greasy Fork / Chrome Web Store
7. **eslint ignore**：补 `dist`、`.output` 历史目录

不在本次做的事：

- 不升级 Vue / React / rspack / TypeScript
- 不重写 Force Copy 的 inject / bridge 架构
- 不合并 `copy` 与 `copy-currency` 为同一个油猴脚本
- 不把油猴打包器换成 rspack
- 不引入新的 UI 库或状态管理

## 7. 影响范围

### 7.1 目录迁移（重命名/移动）

| 现路径                        | 新路径                                                 |
| ----------------------------- | ------------------------------------------------------ |
| `packages/copy`               | `scripts/copy`                                         |
| `packages/copy-currency`      | `scripts/copy-currency`                                |
| `packages/site-modify`        | `scripts/site-modify`                                  |
| `packages/force-copy`         | `extensions/force-copy`                                |
| `packages/clipboard2markdown` | `extensions/clipboard2markdown`                        |
| `rollup.config.js`            | `tooling/rollup.userscript.js`（逻辑下沉，根文件删除） |
| `meta/blank.ts`               | 已删除（不再单独打 meta 文件）                         |
| `.output/`                    | 废弃，改 `dist/userscripts/`                           |

### 7.2 必改配置（不改业务逻辑）

- 根 `package.json` scripts
- `pnpm-workspace.yaml`
- 根 `tsconfig.json` paths / include
- `extensions/force-copy/rspack.config.js` 的 `output.path`
- `extensions/force-copy/package.json` 依赖名（workspace 路径变化后仍用包名 `copy`，workspace 协议可继续）
- `.gitignore`、`.eslintrc.js`
- `.github/workflows/deploy-scripts.yml`
- 根 README、`.output/README.md`（改为 `dist` 说明或删除）

### 7.3 业务代码

第一阶段：仅因 import 路径变化而改（若抽核延后，`copy/src` 相对包内路径可不变）。

第二阶段：`force-copy` 中约 10 处 `copy/src`、`copy-currency/src` 改为 `copy-runtime`。

## 9. 风险与回归

| 风险                               | 应对                                                                   |
| ---------------------------------- | ---------------------------------------------------------------------- |
| 搬家后 workspace 解析失败          | 先 `pnpm install`，确认 `pnpm-workspace` 与各包 `name` 不变            |
| Force Copy 打进油猴专用代码        | 阶段 A 保持现有依赖；阶段 B 只迁已被引用的符号并跑 `lint:ts`           |
| Greasy Fork / gh-pages 旧 URL 失效 | CI 继续发布脚本文件名：`copy.user.js` 等保持不变，只换目录前缀         |
| Windows 构建失败                   | 阶段 A 尽量避免新增 bash；Force Copy 现有 `rm -rf` 可暂留，阶段 C 再换 |
| 浏览器加载路径变化                 | README 明确写出 `chrome://extensions` 加载 `dist/extensions/...`       |

## 10. 验收标准

1. 源码按 `scripts/` 与 `extensions/` 分开，根目录不再有混装的 `packages/`
2. `pnpm run build:scripts` 只产出到 `dist/userscripts/`
3. `pnpm run build:extensions` 只产出到 `dist/extensions/`
4. 三个油猴脚本、Force Copy（Chromium）、clipboard2markdown 行为与重构前一致
5. CI 发布目录与真实产物目录一致
6. 不升级框架、不改站点适配逻辑（除非阶段 B 的纯搬运）
